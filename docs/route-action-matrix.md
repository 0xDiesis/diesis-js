# Route and action authority

Bindings and `getRuntimeCapabilities()` do not establish action admission. Runtime capabilities describe execution mode and witness diagnostics. Select a route using the connected endpoint's documented policy and authoritative operation-specific reads. Unknown or unavailable evidence means the application must stop preparation.

`sendExchangeActionsTransaction` uses the gated raw method and only falls back to the ordinary raw method on method absence under its existing policy. That behavior does not make a refused signed relay action safe to resubmit through another route.

Core source currently parses a signed perpetual V2 relay envelope, while the reviewed public RPC policy still describes the gasless spot baseline. That discrepancy does not qualify perpetual relay use. This matrix leaves it unavailable until the producer documents and validates the exact endpoint, envelope, authoritative reads and financial execution. `getMarkets`/`getMarket` responses describe market observations, not permission to dispatch.

The RPC-shape baseline referenced by the SDK README is node `44bed910b4fd18c29e287ecd49a12982a90ac5bb`. The new local signed-error decoder matches the separately reviewed version-1 producer contract. Neither source comparison nor fixture execution proves the intended network runs either revision.

Read the exact revision recorded in the delivery compatibility manifest before adopting new routes.
